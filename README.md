# Revenue Sentinel

An AI agent that spots repeat customers slowing down before the merchant notices, checks why, takes the smallest action likely to win them back, and proves the result against a control group.

Built for the Razorpay x ISB AI PM Build Challenge (Track 2: Recover and Grow with AI). Runs on **sample data for a fictional brand** (Dewleaf Skincare). Not affiliated with Razorpay.

## How it works

| Step | Who does it | What happens |
|---|---|---|
| Detect | Code (in the browser) | Compares each of ~26,000 customers' buying rhythm with their own normal |
| Investigate and decide | AI agent (Google Gemini, function calling) | Calls tools: stock, last year's pattern, payment problems, who can be messaged, action estimates, past results |
| Guardrails | Code | Checks every AI decision against the merchant's rules (stockouts, seasonal dips, incentive cap, one action at a time) |
| Act | Merchant | Approve, edit or reject with a reason |
| Measure and learn | Code + Supabase | Compares messaged vs held-back customers (simulated responses) and updates the agent's estimates, saved to Supabase |

## Project layout

- `index.html`, `app.js`: the app
- `data/app_data.json`: sample data (generated by `scripts/`)
- `api/agent.js`: forwards one agent round to Gemini, keeping the API key on the server
- `api/memory.js`: reads and writes the agent's memory in Supabase
- `supabase/schema.sql`: database tables
- `scripts/`: Python that generates the sample data

## Environment variables (Vercel)

- `GEMINI_API_KEY`: from Google AI Studio (free tier)
- `GEMINI_MODEL` (optional): defaults to `gemini-2.5-flash`
- `SUPABASE_URL`, `SUPABASE_ANON_KEY`: from the Supabase project

If the AI is unavailable, the app falls back to offline rules so it never breaks.
